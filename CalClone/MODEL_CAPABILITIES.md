# Model capability discovery

Verified 2026-10-30 against the Hugging Face Hub model-card/API documentation through Context7 and [Google's Gemma repository](https://huggingface.co/google/gemma-4-31B-it). Its task is `image-text-to-text` (text + image input, text output).

When selecting or typing a model, Fueli queries `https://huggingface.co/api/models/{owner}/{repository}` for its `id` and `pipeline_tag`. The request contains no provider API key, provider URL, prompts, or photographs. Only exact namespaced repository IDs are used, with a reviewed alias from `gemma-4-31b-it` to Google's actual `google/gemma-4-31B-it` repository. Unknown bare names are not fuzzily matched. The returned repository identity must match the requested one. Requests are debounced, time-limited, and cancellation-aware at the UI boundary.

Published HF task metadata takes precedence over gateway `/model/info` flags. On lookup failure, Fueli uses the reviewed Google model card for this exact Gemma model, then exact models.dev input-modality metadata, then provider hints. Provider restrictions may differ from base-model capabilities; source information is displayed and a successful connection test proves only text connectivity. Unknown tasks remain unconfirmed rather than being treated as vision-capable. No API key for Hugging Face is required; gated/unavailable metadata can fail gracefully.

**Use Anyway** is available when text + vision is unconfirmed, including models absent from the provider list. It displays an alert explaining that AI features may not work properly. Confirming saves the selected provider/model and tests a text request; canceling does not save. Configuration is no longer automatically saved when leaving this form or changing its question policy. Loading the model list does not replace the user's selection.

Tests in `CalCloneTests/ModelCapabilityTests.swift` cover sparse and incorrect gateway flags, published-card precedence, HF task parsing, identity mismatches, unknown tasks, safe repository IDs, and conservative catalog resolution. Manual UI checks: choose an unverified model, tap Use Anyway, cancel and verify the saved configuration is unchanged; repeat and confirm, then reopen Settings to verify persistence. Select Gemma and verify Text + Vision and the HF/Google source. Test offline lookup and an endpoint that rejects images. Base-model metadata cannot guarantee that a gateway enables image requests.

Simulator verification (2026-10-31): the configured gemma-4-31b-it displayed Text + Vision and the exact Hugging Face publisher URL. Temporarily editing the model to unverified-test-model exposed Use Anyway; the warning explicitly said AI features may not work properly, including photo analysis. Canceling the alert, leaving settings and reopening retained gemma-4-31b-it. No new provider/model configuration or API key was saved during this check.
